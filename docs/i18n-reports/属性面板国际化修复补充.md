## 问题描述

在修复过程中发现了一个额外的问题：

**文件**: `apps/web/src/components/editor/panels/properties/registry.tsx`

**错误类型**: 运行时错误
```
src/components/editor/panels/properties/registry.tsx (140:10) @ buildAudioTab
> 140 |         label: zh["property.audio"],
      |                ^
ReferenceError: zh is not defined
```

## 根本原因

该文件使用了一个特殊的 `getTranslations()` 函数来处理非组件上下文，但有 5 个函数忘记调用它：

1. `buildAudioTab` - 音频标签
2. `buildSpeedTab` - 速度标签
3. `buildClipEffectsTab` - 剪辑特效标签
4. `buildTextTab` - 文字标签
5. `buildStandaloneEffectTab` - 独立特效标签

这些函数直接使用了未定义的 `zh` 变量，导致运行时错误。

---

## 文件架构说明

这个文件比较特殊，它不在 React 组件上下文中，因此不能使用 `useLocale()` hook。

**解决方案**：使用 `getTranslations()` 辅助函数
```typescript
// 定义在文件顶部
const getTranslations = () => {
  if (typeof window !== "undefined" && window.localStorage) {
    const savedLocale = localStorage.getItem("locale") as "zh" | "en" | null;
    return getLocale(savedLocale || "zh");
  }
  return getLocale("zh");
};

// 在每个函数中使用
function buildAudioTab(...) {
  const t = getTranslations();
  return {
    label: t["property.audio"], // ✅ 正确
    // ...
  };
}
```

## 技术细节

### 为什么不能使用 useLocale()?

这个文件导出的函数在组件渲染之外被调用，它们用于配置属性面板的结构。因此：

- ❌ 不能使用 React hooks（`useLocale`）
- ✅ 必须使用直接访问 localStorage 的方式

### getTranslations() 的工作原理

```typescript
const getTranslations = () => {
  // 1. 检查是否在浏览器环境
  if (typeof window !== "undefined" && window.localStorage) {
    // 2. 从 localStorage 读取保存的语言设置
    const savedLocale = localStorage.getItem("locale") as "zh" | "en" | null;
    // 3. 返回对应语言的翻译对象
    return getLocale(savedLocale || "zh");
  }
  // 4. 服务端渲染时使用默认中文
  return getLocale("zh");
};
```

### 局限性

这种方法的局限性：
- 需要刷新页面才能看到语言变化（不像 useLocale 那样自动）
- 但这对属性面板标签来说是可以接受的，因为它们在页面加载时初始化
