02

信息架构

结构

导航收敛为四项，外加「返回编辑器」。删除独立的「服务商密钥」入口 —— 模型配置成为唯一入口，承担四类信息：接口（路由 + 密钥）/ 能力 / 定价 / 文案。

导航项职责
用户管理搜索、封禁、角色、套餐
模型配置模型的接口、能力、定价、文案 —— 唯一配置入口
计费管理手动调整点数、批量生成兑换码
审计日志所有写操作的留痕，可按动作筛选
返回编辑器离开管理面板

05

密钥的两层覆盖

交互

每条路由的密钥有三种状态。之所以不把密钥做成「每个模型各存一份」： 同一个 fal 密钥会在 4 个模型上各存一份密文，轮换时要改 4 处且容易漏。 两层结构下，共用密钥轮换只改一处，同时保留「某个模型单独换账号」的能力。

图 03密钥字段的三种状态
状态 ① · 共用默认
密钥 共用 ····c123

服务商有一份密钥，本模型没有覆盖。这是默认状态， 也是绝大多数模型应该停留的状态。

状态 ② · 模型专属
密钥 模型专属 ····x789

本模型单独使用另一份密钥（例如独立账号或独立配额）。 「清除覆盖」会回退到服务商共用密钥，不会删除共用密钥本身。

状态 ③ · 输入中
密钥 ••••••••••••

只写不读：输入框永不回显已存密钥，留空保存即不修改。 已配置时只显示末 4 位；审计日志同样只记末 4 位。

优先级规则要写在界面上，不能只写在文档里。 顺序为：模型专属密钥 → 服务商共用密钥 →（仅火山方舟）环境变量。 两层都没有时，该路由从降级链中剔除；若一个模型所有路由都被剔除， 列表页显示 ⚠ 无密钥。 抽屉里每条路由下方都常驻这一行说明。
标注
  • 8 三态共用同一个字段位置， 只切换形态与文案，不新增弹窗或二级页面。 「覆盖」与「清除覆盖」都是就地操作。

08

需要的新后端能力

实现

这不是纯前端改动。诚实列出改动量，避免被当成样式调整。

改动内容
新表 modelRouteSecrets：(modelId, provider) 主键、 apiKeyEnc、apiKeySuffix、updatedBy、 updatedAt；外键到 aiModels 级联删除
解析逻辑 resolveRouteCredential(modelId, provider)： 模型覆盖 → 服务商默认 →（仅 ark）环境变量
链路判定 resolveProviderChain 改为「两层密钥任一存在」即视为可用
列表派生字段 listModels 增加 usableRoutes 与 hasUsableCredential —— 只返回布尔值，绝不带密钥
接口 PUT / DELETE /api/admin/models/[id]/routes/[provider]/secret 写入与清除覆盖；toPublicModel 白名单扩展新派生字段但排除密钥
删除 移除 /admin/credentials 页面、导航项与其 API
与已实现版本的差异（重要）。 上一轮已经落地了一版：模型编辑是独立页面 /admin/models/[id]， 密钥在独立页面 /admin/credentials。本方案会替换掉这两处 —— 独立编辑页改为抽屉，密钥页整页作废。 数据库、按协议族归类的 provider 策略、加密存储、审计这些都复用，不动。
09

实施顺序

实现

每一步都能独立验证，前端依赖后端就绪后再接。

  1. 01新表 + 迁移 + resolveRouteCredential + 链路判定（纯后端，可独立验证）
  2. 02覆盖用 API（PUT / DELETE）+ 审计留痕
  3. 03listModels 派生字段 + toPublicModel 扩展（重点验证不泄漏）
  4. 04模型列表页重做（汇总条 + 接口 chip + 「⚠ 无密钥」）
  5. 05抽屉组件 + 密钥三态接入 API + 保存栏
  6. 06顶栏提权状态、审计筛选分页、用户页确认弹窗
  7. 07移除 /admin/credentials 及其 API
10

待确认的取舍

决策
取舍理由与风险
审计页加筛选 + 分页 超出「纯展示重做」的范围。但它现在只给最近 100 条且无法翻页，实际查不了历史。可以砍掉。
封禁理由改用弹窗 行内输入更轻快，写长理由很挤。可以保留行内。
「⚠ 无密钥」标记 本方案新加的信息，需要后端多算一个派生布尔值。收益是让「配了但跑不起来」这种静默失败变得可见。
两层密钥覆盖 比「每模型一份」复杂，界面上要同时解释两层优先级。收益是共用密钥只存一份、轮换只改一处。

确认后按第 09 节顺序实现。上一轮的改动尚未提交，本次会替换其中一部分， 建议先为上一轮落一个提交再继续。
