00

概览

SUMMARY

当前项目是 OpenCut 视频编辑器的自建分支（Next.js 16 + React 19 + WASM 合成）， 已叠加账号、管理、计费与 AI 生成体系。本节给出全局判断：哪些底座已就绪、哪些缺口需要补齐。

现状 · 素材

本地素材 100% 客户端

文件存浏览器 OPFS，元数据存按项目隔离的 IndexedDB，服务端零存储。编辑器只认 File 对象——云端素材还原成 File 即可零改动接入。

现状 · 账号

就绪账号 / 计费 / 审计

users、credit_ledger、channels（密钥加密）、audit_log、RLS 齐备。缺口：无素材归属、分享、上传相关表。

现状 · AI

策略模式缺文生图

protocols 协议族 + DB 通道已落地，密钥 100% 服务端。已有视频生成 / 抠图 / 擦除 / 音乐，尚无文生图。

现状 · 部署

三套底座Cloudflare 优先

opennextjs-cloudflare + 外置 PG/Redis；Railway 与 Docker 自托管备选。无后台队列，AI 生成走请求内提交+轮询。

目标 · 1

OSS 云端化

自建对象存储私有空间，生成素材与上传素材统一落库，跨设备 / 跨项目可用。

目标 · 2

归属与分享

素材挂账号（user_id），分享链接 + 复制到我的库，合规下架兜底。

目标 · 3

七牛云模型

生图（AI Token API，gemini 系列）+ 生视频（Vidu），全部走管理面板配置，无代码硬编码。

目标 · 4

可上线部署

上传直传绕开 Workers 限制，私有空间签名 URL，成本与合规可控。

CONVENTIONS · 既有约定（规划必须遵守）
  • 策略模式：协议相同的厂商归一个 protocol 实现，通过模型 id 路由；状态词在策略内部归一（pending / done / failed），不向 UI 泄漏原始状态词。
  • 密钥不出服务端：供应商密钥只存 channels.api_key_enc，客户端只发 modelId + refId + 参数；管理面板返回的 ChannelView 永不含密钥。
  • 管理面板交互：/admin/* 编辑控件「即刻生效 + 直接增删实体」，不额外做保存条。
  • 计费单点：成本一律由服务端从 ai_models 重新计算（客户端不可信），冻结 / 结算走幂等账本。
  • 全表 RLS：新表必须开 RLS 并声明策略（归属行 / 分享行）。
03

目标架构

TARGET

新增能力后的整体形态。核心原则：编辑器零改动、密钥不出服务端、归属即账号、小步可上线。

DATA FLOW · 素材数据流
① 上传 / 生成 客户端 ──POST /api/assets/upload-token──▶ 服务端签发限时 presigned 上传 URL（限定 key 前缀 u/<user_id>/…） 客户端 ──直传（S3 兼容 SDK / 裸 PUT）──▶ 自建 OSS 私有空间 客户端 ──POST /api/assets/register──▶ 服务端校验 key 归属 → 写 media_assets → 写 audit_log ② 消费 GET /api/assets/<id>/file → 校验归属 / 分享授权 → 私有签名 URL（短时效） 客户端下载为 Blob → 构造 File → 走现有 addMediaAsset 管线（编辑器零改动） ③ 分享 素材 → 创建 asset_shares（token / view|copy / 过期时间）→ /share/a/<token> 复制 = 新建独立 media_assets 行（对象级拷贝，生命周期解耦）
DB · 新增表

media_assets

素材元数据与归属：id · user_id · key(OSS键) · name · type · mime · size · width/height/duration · thumbnail_key · source(upload/ai_generate/share_copy) · created_at。RLS：本人可读写，分享授权者只读。

DB · 新增表

asset_shares

分享记录：id · asset_id · token(短随机) · permission(view/copy) · expires_at(可空=永久) · created_by · created_at。撤销即删行，副本不受影响。

AI · 新增协议

qiniu-image / qiniu-video

七牛 AI Token API（生图，gemini 系列）与七牛大模型推理服务（Vidu 生视频）各实现一个 Protocol；通道与定价全部走管理面板，无代码硬编码。

部署方案

DEPLOY

三个既有部署底座全部兼容 OSS 方案；按用户群选主推。

方案 A · 主推

Cloudflare Workers

  • opennextjs-cloudflare 构建，wrangler 部署（已配置）
  • 外置 PostgreSQL + Redis（Upstash / 自建）
  • 自建 OSS：客户端直传，避开 Workers 请求体限制
  • 适用：海外 / 全球用户，边缘就近
方案 B · 国内首选

Railway / 国内主机

  • railway.toml 已配置，Docker 化部署
  • 自定义域名 + CDN 加速（国内直连，自建 OSS 前置）
  • PG / Redis 与主机同区，延迟最低
  • 适用：用户以国内为主（当前实际情况）
方案 C · 兜底

Docker 自托管

  • docker-compose.yml 已含 db + redis + web 全套
  • 任意云主机 / 内网可用，数据完全自持
  • serverless-redis-http 包装本地 Redis 兼容 Upstash
  • 适用：私有部署、离线场景

06

风险与决策点

DECISIONS

需要拍板的事项，均已给出推荐（绿字）。

1
自建 OSS 的对接协议？

按 S3 兼容协议（MinIO / SeaweedFS / 自研等）对接；media_assets.key 是纯对象键、签名逻辑集中在服务端一层，未来可平滑迁移。推荐：S3 兼容协议。需确认：具体服务形态、是否支持 presigned URL、有无 CDN 与图片处理能力。

2
分享「复制」的语义：对象拷贝还是引用计数？

对象级拷贝：副本独立于原素材（撤销分享不影响副本），代价是重复存储；引用计数省空间但生命周期纠缠、下架复杂。推荐：对象拷贝，P1 后评估去重。

3
生图 / 生视频定价策略？

七牛 MaaS 聚合多家（gemini 系列生图、Vidu 生视频），定价随上游浮动；ai_models 已支持管理面板改价。推荐：上线初期加 20-30% 毛利，周度对账。

4
部署目标：Cloudflare 还是国内？

Workers 域名国内访问质量不稳定；用户主站在国内时，应自定义域名 + 国内 CDN 回源，或直接 Railway / 国内 Docker 主机。推荐：用户以国内为主，优先 Railway 或国内主机 + CDN（自建 OSS 前置）。

5
生成素材的内容合规？

素材落库即发布，需要审核兜底。推荐：上线前接七牛内容审核 API，或先人工巡检 + 举报下架。

6
现有本地素材去留？

编辑器继续支持纯本地模式（离线友好），云端是可选增强。推荐：不强制迁移，云端素材提供「下载到本地」双向通道。
