# OpenCut Classic 架构与部署方案

> 基于仓库 `opencut-classic-main` 梳理。注意：本仓库是 **OpenCut 的原始代码库（Legacy）**，已在 README 中标明"已归档、不再维护"，重写版在 `opencut-app/opencut`。下文描述的是当前仓库的实际情况。

---

## 一、项目定位

OpenCut 是一个**本地优先、开源、免费**的视频编辑器，定位是 CapCut 的替代品。核心卖点：

- **隐私**：视频默认保留在用户设备上（浏览器本地 / 桌面端本地）。
- **免费**：多数基础剪辑功能免费，不付费墙。
- **简单**：编辑器交互轻量易上手。

参与的技术赞助/集成方：Vercel（OSS 计划）、fal.ai、MarbleCMS（图片素材）、Freesound（音效）、火山方舟（AI 视频生成）。

## 二、总体架构（Monorepo）

整个项目是一个 **Bun workspace + Turborepo** 管理的单仓库（monorepo），根 `package.json` 定义了 `apps/*` 与 `packages/*` 两个 workspace。根目录 `Cargo.toml` 又是一个 Rust workspace，两套包管理共存。

### 2.1 核心分层原则（来自 `AGENTS.md`）

> 一次进行中的迁移把**所有业务逻辑**搬进 `rust/`。每个 `apps/` 下的应用只是 **UI shell** —— 它负责渲染、交互和平台相关的事，但**永远不拥有业务逻辑**。任意应用的 UI 框架都是可替换的细节。

这是整个架构的灵魂：

- 逻辑（logic）**唯一真源**在 `rust/` —— 不能有组件、hooks 或框架 import。
- 各 app 之间**逻辑永不重复**，只有 UI 会重复（因为不同平台可能用完全不同的框架和语言）。
- 一个 app = 一个前端，通过调用 Rust 来工作。

### 2.2 顶层目录职责

```
opencut-classic-main/
├── apps/            # 各平台的 UI shell
│   ├── web/         # Next.js Web 应用（当前主力，最成熟）
│   └── desktop/     # GPUI 原生桌面应用（进行中/WIP）
├── rust/            # 所有非 UI 代码的唯一真源（平台无关）
│   ├── crates/      # 业务库：compositor/effects/gpu/masks/time/bridge
│   └── wasm/        # 把 crates 编译成 WASM 包 opencut-wasm
├── docs/            # 架构与子系统文档（actions/effects-renderer/keyframes 等）
├── script/          # 环境设置脚本（setup-rust 等）
├── notes/           # 设计笔记
├── .github/         # CI / 贡献指南 / issue 模板
├── docker-compose.yml   # 本地与自托管编排
├── railway.toml         # Railway 平台部署配置
└── wrangler.jsonc       # Cloudflare Workers 部署配置
```

### 2.3 Rust 核心（`rust/`）

由六个 crate 组成一个 Cargo workspace，全部平台无关（无框架、无 DOM 依赖）：

| crate | 职责 |
|-------|------|
| `time` | 时间基元：媒体时间（ticks）、时间码、帧率 |
| `bridge` | 桥接/序列化（与 JS 边界交互） |
| `compositor` | 帧合成器：blend mode、texture pool、shader |
| `effects` | 特效：管线、类型、shader |
| `gpu` | 图形上下文抽象（含 wasm 特性） |
| `masks` | 遮罩：SDF 距离场、羽化、shader |
| `wasm` | 顶层包，`wasm-pack` 编译为 `opencut-wasm@0.2.10`，导出到 JS |

`rust/wasm/src/wasm.rs` 是入口：在 `wasm32` 目标下 re-export `compositor/effects/gpu/masks/perf` 各模块，并带出 `time`。产出物是一个**已发布的 npm 包**（`opencut-wasm`），Web 应用默认 `bun install` 安装，而不是源码引用。

Web 应用里对应的 TS 封装在 `apps/web/src/wasm/`（如 `media-time.ts`），而 WebGL/Canvas 渲染层在 `apps/web/src/services/renderer/`（`wasm-compositor.ts`、`gpu-renderer.ts`、`canvas-renderer.ts`）。

## 三、Web 应用（`apps/web/`）

这是当前唯一完整可运行的前端。

### 3.1 技术栈

- **Next.js 16.1.3**（App Router，Turbopack dev，`output: "standalone"`）
- **React 19** + TypeScript
- **Tailwind CSS 4**（PostCSS）
- **Zustand** —— 状态管理（编辑器 store、panel store 等）
- **Drizzle ORM** + **PostgreSQL** —— 数据层
- **better-auth** —— 认证（邮件/社交账户）
- **@upstash/redis** + **@upstash/ratelimit** —— 限流
- **Radix UI / shadcn 组件体系**（`components.json`）
- **WASM（opencut-wasm）** + **WebGL/compositor** —— 渲染合成
- **@huggingface/transformers** —— 本地 AI/转写
- **mediabunny、wavesurfer.js、soundtouchjs** —— 音视频解析/波形/变速
- **@opennextjs/cloudflare** —— 部署到 Cloudflare Workers
- **content-collections、@napi-rs/canvas** —— 静态内容与图形生成

### 3.2 编辑器核心（`src/core/`）

`EditorCore` 是一个单例（`src/core/index.ts`），聚合了所有领域 manager：

`TimelineManager`、`CommandManager`（命令/撤销栈）、`PlaybackManager`、`ScenesManager`、`ProjectManager`、`MediaManager`、`RendererManager`、`SaveManager`、`AudioManager`、`SelectionManager`、`ClipboardManager`、`DiagnosticsManager`。

初始化时会 `registerDefaultEffects()` / `registerDefaultMasks()` 注册默认特效与遮罩。UI 侧通过 `src/editor/`（`editor-store.ts`、`use-editor.ts` 等）消费这个核心。

按领域拆分的命令树在 `src/commands/`（`media/project/scene/timeline`），timeline 下又分 `clipboard/element`（含 effects/keyframes/masks）/`track`。动作与快捷键在 `src/actions/`、`src/actions/keybindings/`。

### 3.3 数据层

Schema（`src/db/schema.ts`）包含：`users`、`sessions`、`accounts`、`feedback`、`verifications`，多数表启用了 **RLS（Row Level Security）**。迁移文件在 `apps/web/migrations/`（Drizzle 生成）。`drizzle.config.ts` 依 `NODE_ENV` 读取 `.env.local` 或 `.env.production`，dialect 为 postgresql。

### 3.4 API 路由（`src/app/api/`）

| 路由 | 用途 |
|------|------|
| `/api/auth/[...all]` | better-auth 认证 |
| `/api/health` | 健康检查（`GET` 返回 `"OK"`） |
| `/api/feedback` | 收集用户反馈 |
| `/api/media/download` | 媒体下载代理 |
| `/api/sounds/search` | Freesound 音效搜索（使用 `FREESOUND_CLIENT_ID/API_KEY`） |
| `/api/ai-video/generate` | 调用**火山方舟** `doubao-seedance-2-0-260128` 创建视频生成任务（ark 的 API key 仅服务端使用，返回 taskId 供轮询） |
| `/api/ai-video/status` | 轮询方舟生成状态 |

### 3.5 页面（`src/app/`）

`/editor/[project_id]`（编辑器主界面）、`/projects`（项目列表）、`/blog`、`/changelog`、`/roadmap`、`/sponsors`、`/contributors`、`/privacy`、`/terms`、`/brand`、`/rss.xml`。

### 3.6 第三方/外部依赖

- **MarbleCMS**（`NEXT_PUBLIC_MARBLE_API_URL`、`MARBLE_WORKSPACE_KEY`）—— 图片素材/内容源。
- **Freesound** —— 音效素材。
- **火山方舟 Ark**（`ARK_API_KEY`，可选）—— AI 视频生成。
- **Vercel / Cloudflare / Railway** —— 托管部署（见下文）。

## 五、部署方案

本仓库为同一个 Web 应用提供了**三种**部署目标，外加本地开发的 Docker 编排，环境变量通过 `apps/web/src/env/web.ts`（zod 校验）在运行时做强校验。

### 5.1 方案一：Docker 自托管（`docker-compose.yml`）

一套编排同时拉起全部服务，即"一条命令把包括生产构建在内的整个应用跑起来"。

**服务清单：**

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| `db` | `postgres:17` | `5432` | PostgreSQL，`opencut/opencut`，卷 `postgres_data` |
| `redis` | `redis:7-alpine` | `6379` | 缓存/会话 |
| `serverless-redis-http` | `hiett/serverless-redis-http:latest` | `8079:80` | 把 Redis 包装成 Upstash REST 接口（`UPSTASH_REDIS_REST_URL/TOKEN`），让应用能以 Upstash 兼容方式连本地 Redis |
| `web` | 本地 Dockerfile 构建 | `3100:3000` | 生产构建的 Next.js 应用 |

`web` 构建时传入 build args：`FREESOUND_CLIENT_ID`、`FREESOUND_API_KEY`、`NEXT_PUBLIC_MARBLE_API_URL`（默认 `https://api.marblecms.com`）、`MARBLE_WORKSPACE_KEY`、`NEXT_PUBLIC_SITE_URL`。

运行时 `web` 的关键环境变量：
- `DATABASE_URL=postgresql://opencut:opencut@db:5432/opencut`
- `BETTER_AUTH_SECRET`
- `UPSTASH_REDIS_REST_URL=http://serverless-redis-http:80`、`UPSTASH_REDIS_REST_TOKEN=example_token`
- `NEXT_PUBLIC_SITE_URL=http://localhost:3100`
- Marble/Freesound 相关

`depends_on` 保证了 `web` 在 `db` 与 `serverless-redis-http` 健康后才启动。健康检查：`web` 用 `curl http://localhost:3000/api/health`。默认网络名 `opencut-network`。

> 本地开发时，可只启动数据库与 Redis 跑前端：`docker compose up -d db redis serverless-redis-http`，再 `bun install && bun dev:web`（访问 `http://localhost:3000`）。

### 5.2 方案二：Cloudflare Workers（`wrangler.jsonc` 根 + `apps/web/wrangler.jsonc`）

借助 **@opennextjs/cloudflare** 把 Next.js standalone 构建产物适配到 Cloudflare Workers：

- 根 `wrangler.jsonc`：`name: "opencut"`，`main: .open-next/worker.js`，`compatibility_date: 2025-04-01`，`compatibility_flags: ["nodejs_compat", "global_fetch_strictly_public"]`。
- 静态资源目录 `.open-next/assets` 绑定为 `ASSETS`；`services` 配置了 `WORKER_SELF_REFERENCE` 自引用。
- 部署脚本：`bun run deploy:web` → `opennextjs-cloudflare build && opennextjs-cloudflare deploy`（在 `apps/web/package.json`），本地预览为 `preview` 脚本。
- `apps/web/open-next.config.ts` 使用默认 `defineCloudflareConfig()`。

> 这条链路依赖数据库/Redis 为**外部托管**（如 Upstash 云 Redis、托管 Postgres），因为 Workers 无持久磁盘。

### 5.3 方案三：Railway（`railway.toml`）

- `[build]`：`builder = "DOCKERFILE"`，`dockerfilePath = "apps/web/Dockerfile"` —— 复用同一个 Dockerfile，Railway 会把服务变量作为 build arg 传入（覆盖库内默认值）。
- `[deploy]`：`healthcheckPath = "/api/health"`，`healthcheckTimeout = 300`，`restartPolicyType = "ON_FAILURE"`，`restartPolicyMaxRetries = 10`。

### 5.4 方案四：Vercel

README 提到项目参与 **Vercel OSS Program**（含 Vercel 徽标）。`next.config.ts` 的 `output: "standalone"` 与 App Router 也天然适配 Vercel 平台部署。

### 5.5 Web 容器的多阶段构建（`apps/web/Dockerfile`）

PHP 使用 **oven/bun:alpine** 基础镜像，分三阶段：

1. **base** → `oven/bun:alpine`。
2. **builder**：
   - 拷贝根 `package.json`、`bun.lock`、`turbo.json` 与 `apps/web/package.json`，`bun install`。
   - 拷贝 `apps/web/` 源码。
   - 设 `NODE_ENV=production`、`NEXT_TELEMETRY_DISABLED=1`。
   - 用 **build-time env 桩值** 通过 zod 校验（`DATABASE_URL`、`BETTER_AUTH_SECRET`、`UPSTASH_REDIS_REST_URL/TOKEN`、`NEXT_PUBLIC_*`、Marble/Freesound 的占位值）——因为 `env/web.ts` 在构建期就会 parse，必须给合法占位。
   - `bun run build`（Next standalone 构建）。
3. **runner**（生产镜像）：
   - 以非 root 运行（`nodejs`/`nextjs` uid 1001）。
   - 拷入 `public`、`.next/standalone`（解到根，含 `server.js`）、`.next/static`。
   - `EXPOSE 3000`，`CMD ["bun", "apps/web/server.js"]`，`HOSTNAME=0.0.0.0`。

### 5.6 CI（`.github/workflows/bun-ci.yml`）

`Bun CI` workflow 在 push/PR 到 `main` 时触发（忽略 `*.md`）。

- 矩阵：`ubuntu-latest / windows-latest / macos-latest` 三 OS。
- 步骤：checkout → `rustup target add wasm32-unknown-unknown` → 安装 `wasm-pack` → 缓存 Rust 产物 → `wasm-pack build rust/wasm --target bundler` → 安装 Bun 1.2.18 → 缓存 Bun 模块 → `bun install`（在 `apps/web`）→ `bun run build` → 跑测试（当前为占位 `echo "No tests implemented yet"`）。
- 环境变量使用占位值（`DATABASE_URL=postgresql://...@localhost:5432/opencut` 等）以满足构建期 zod 校验。

## 六、本地开发起步

前置：**Bun**、**Docker**（可选，用于本地数据库/Redis）。

```bash
# 1) 复制环境文件
cp apps/web/.env.example apps/web/.env.local     # Unix/Linux/Mac
# Windows PowerShell: Copy-Item apps/web/.env.example apps/web/.env.local

# 2) 起数据库与 Redis
docker compose up -d db redis serverless-redis-http

# 3) 安装依赖并启动开发服务器
bun install
bun dev:web
# 访问 http://localhost:3000
```

`.env.example` 的默认值与 Docker Compose 配置匹配，通常开箱即用。

**本地 WASM 开发**（仅当修改 `rust/wasm` 且希望 Web 使用本地构建时）：安装 Rust + `wasm-pack` + `cargo-watch`，`bun run build:wasm`，到 `rust/wasm/pkg` 执行 `bun link`，再到 `apps/web` 执行 `bun link opencut-wasm`，开发时用 `bun dev:wasm` 增量重建。（Web 默认走已发布的 `opencut-wasm` 包。）

## 八、总结

- **架构**：平台无关的 Rust 核心（`rust/crates`，编译成 `opencut-wasm`）= 逻辑唯一真源；`apps/web`（Next.js 16）与 `apps/desktop`（GPUI）只是调用它的 UI shell。Web 端又用 Zustand `EditorCore` 单例将各领域 manager 聚合，用 Drizzle + Postgres 持久化，用 Upstash/Redis 限流，依靠 WASM + WebGL/Canvas 做渲染合成。
- **部署**：一套代码，多目标 —— Docker Compose 自托管（Postgres + Redis + serverless-redis-http + web，`3100` 端口）、Cloudflare Workers（opennextjs-cloudflare 适配，需要外部 DB/Redis）、Railway（复用 Dockerfile，健康检查 `/api/health`）、以及 Vercel。环境变量统一走 `env/web.ts` 的 zod 校验，Dockerfile 用构建期桩值通过校验，运行时再替换为真实值。

> ⚠️ 提醒：此仓库已标记为归档、不再维护（Legacy），重写版在 `opencut-app/opencut`。若用于新项目，建议参考新仓库而非此库。
