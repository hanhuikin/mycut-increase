对话框关闭生成状态提升到独立 store（不随对话框卸载丢失）——关掉再开进度续上；全部完成后 toast「多图生图完成 · 已入库 N 张」

3.5 校验与边界

场景处理
选中含视频动作条只计图片，视频显示「未计」；进对话框仅带图片
选中 > 4 张图片「多图生图」置灰 + tooltip 提示取消多余张数（不静默截断）
单图 > 10MB / 非图片进对话框时该图槽位禁用 + 原因文案（复用 picker 的 blockedReason 模式）
对话框打开期间素材被删打开时按 id 重查一次；缺失的槽位置灰提示「素材已删除」，可移除
请求体体积M1 必做：参考图入槽时前端压缩（canvas 重采样长边 ≤1536 + JPEG 0.9）再转 dataURL——4 张原图直传 base64 可达 50MB+ 请求体，压缩后单图 ~300KB、总 ~1.6MB
余额不足预估 > 余额时生成置灰 + 余额红字 + 兑换入口；402 响应同 AI 视频文案
上游失败 / 超时失败卡 + 错误摘要；冻结自动退（refund 幂等）；重试 = 新 refId 重新冻结
每日上限模型 dailyLimit 429 文案 + 明日恢复时间（与 AI 视频同源）
重复打开对话框同一时刻仅一个生成中对话框；已有进行中任务时重开显示进行中状态（store 恢复）

七、界面优化方案（v2 · 四选一，2026-11-18）

现状问题（对照首版实现的截图）： ① 参考图槽位过大且高度不齐，占据对话框一半以上纵向空间；② 「+ 上传」「+ 图库」两个独立按钮悬空在槽位右侧，视觉割裂； ③ 提示词 textarea 底色发蓝（bg-secondary 在暗色下突兀）；④ 建议 chips / 参数 / 成本 / 生成按钮各行散排，缺乏分组与层次； ⑤ 结果区出现后对话框被撑得很长；⑥ 整体观感与编辑器既有面板（AI 视频/任务抽屉）不一致。 以下四套方案都建立在「公共优化项」之上，差异在整体布局形态。
